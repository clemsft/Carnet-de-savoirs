# Audit du Carnet de Savoirs — 18 août 2026

Périmètre : `app.js` (10 325 lignes, lues intégralement en 7 tranches), `styles.css`, `index.html`, `sw.js`, `manifest.json`, `Update-Cache-Version.ps1`, `Snapshot.bat`, les 68 sujets et les 10 parcours (vérifiés par script). Chaque point ci-dessous a été vérifié dans le code (numéro de ligne cité). Les lignes se réfèrent à `app.js` sauf mention contraire.

Déjà corrigé aujourd'hui : la course de chargement KaTeX (widget `Equation`) — patch livré dans `app.js`.

---

## 1. Synthèse

L'application est solide dans son architecture (IIFE unique, état centralisé, validation des sujets, échappement HTML systématique dans `md()`), riche en fonctionnalités et globalement bien commentée. Les défauts trouvés relèvent surtout de trois familles récurrentes :

1. **Effets de bord dans les fonctions de rendu** : plusieurs écrans « final » (quiz, quiz mixte, champion) enregistrent la tentative, l'activité ou le record *à chaque affichage* — donc plusieurs fois si l'on revient sur l'écran. Cela gonfle les statistiques, la heatmap et les streaks.
2. **Cycle de vie non maîtrisé** : timers, `IntersectionObserver`, écouteurs `document`/`window` et overlays plein écran ne sont pas nettoyés quand la route change. Conséquences : fuites, double comptage, chronos qui tournent en arrière-plan, overlays qui restent bloqués.
3. **Robustesse des données** : import JSON sans validation, migration de l'état qui ne s'exécute jamais, dates parsées en UTC puis comparées en local, parseur de dates de la Timeline qui place 1986 en -26.

À cela s'ajoutent des écarts entre ce que promet `TEMPLATE_SUJET.md` et ce que fait le code (markdown non rendu dans les seuils de curseur — 7 sujets concernés), un service worker qui ne permet en réalité pas le hors-ligne, et un manifest PWA non installable sur Chrome.

Aucune faille XSS exploitable depuis l'extérieur (tout le contenu est local), mais deux champs de sujet (`quiz[].explication`, l.3885 et l.9925) sont injectés bruts en `innerHTML` alors que tout le reste passe par `md()`.

## 3. Écarts entre TEMPLATE_SUJET.md et le code

Le template est ce que Claude lit pour générer les fiches ; ces écarts produisent des erreurs à chaque nouveau sujet.

- §6 dit que `seuils[].description` supporte le markdown → **faux** (voir M15). Inversement, `SelecteurValeurs.description` est annoncé « texte simple » → **faux**, `md()` est appliqué (23 sujets s'en servent déjà). Le récapitulatif exact des champs : `md()` → `contenu_md`, descriptions de SelecteurValeurs / GrilleCartes / ListeMethodes / Frise / hotspots, `points_cles`, `vocabulaire.definition`, `carte_mentale.description`. `textContent` → seuils (titre + description), `presets.label`, `tag`/`titre` de cartes, `titre` de méthodes, `date`/`titre` de frise, `legende` d'Equation et SchemaAnnote, `label` de hotspot, quiz.
- « Erreur courante n°4 » (`jusqua: Infinity` obligatoire) est fausse : l.3252 retombe sur le dernier seuil.
- Deux widgets existent dans le code mais pas dans le template : `TableauComparatif` (l.3568) et le bloc `mini-quiz` (l.2954). `CurseurParametrique` accepte `presets` (non documenté). `Equation` accepte `variables`/`compute` (mode manipulable, non documenté).
- Le commentaire de code l.3179 dit `degradePiste: "linear-gradient(...)"` alors que le CSS enveloppe déjà la valeur ; c'est le template qui a raison.
- Le template ne mentionne pas les 4 autres types de questions de quiz (`vrai-faux`, `ordre-chrono`, `texte-a-trou`, `associer`) pourtant implémentés et validés (l.282-305).
- `README.md` et `BRIEFING_COWORK.md` sont périmés (1 200 lignes annoncées pour app.js, 4 widgets, roadmap listant des choses déjà faites).
